বাংলাদেশের API ল্যান্ডস্কেপ: কী সংযুক্ত করা যায়, কী যায় না

ইন্টিগ্রেশন কোডের একটি লাইনও লেখার আগে, বাংলাদেশের ডিজিটাল ইকোসিস্টেম সম্পর্কে একটি মৌলিক সত্য বুঝে নিতে হবে। API-র মান এখানে ব্যাপকভাবে ভিন্ন — ভালোভাবে ডকুমেন্টেড REST API (bKash, SSLCommerz) থেকে শুরু করে সামান্য ডকুমেন্টেড SOAP সার্ভিস (কিছু ব্যাংকের কর্পোরেট পোর্টাল), এমনকি একেবারেই API না থাকা সিস্টেম পর্যন্ত (NBR-এর iBAS++ ব্রাউজার অটোমেশন চায়, API কল নয়)।

বাংলাদেশের ব্যবসাগুলো সাধারণত Odoo-র সাথে যা যুক্ত করতে চায় এবং প্রতিটির জন্য বাস্তবসম্মত ইন্টিগ্রেশন লেভেল কী — তার একটি ব্যবহারিক মানচিত্র এখানে দেওয়া হলো:

bKash Merchant API REST + OAuth 2.0

ভালোভাবে ডকুমেন্টেড REST API। পেমেন্ট শুরু করা, স্ট্যাটাস চেক এবং রিফান্ড সাপোর্ট করে। IP হোয়াইটলিস্টিং ও স্যান্ডবক্স টেস্টিং প্রয়োজন। কাস্টম Odoo মডিউল লাগবে।

Nagad Merchant API REST + RSA এনক্রিপশন

ডকুমেন্টেড, তবে প্রতিটি রিকোয়েস্টে RSA কী-পেয়ার এনক্রিপশন ব্যবহার করে। bKash-এর চেয়ে জটিল। বাংলাদেশে রেজিস্টার্ড ব্যবসা লাগবে। কাস্টম মডিউল প্রয়োজন।

SSLCommerz REST, ভালো ডকুমেন্টেশন

বাংলাদেশের সবচেয়ে ডেভেলপার-ফ্রেন্ডলি পেমেন্ট গেটওয়ে। একটি গেটওয়েতেই bKash, কার্ড, মোবাইল ব্যাংকিং সাপোর্ট করে। PHP/Python SDK পাওয়া যায়। Odoo ই-কমার্সের জন্য সবচেয়ে সহজ ইন্টিগ্রেশন পয়েন্ট।

Pathao Courier API REST + API key

API key অথেন্টিকেশনসহ REST API। অর্ডার তৈরি, ট্র্যাকিং, স্ট্যাটাস পরিবর্তনে ওয়েবহুক কলব্যাক সাপোর্ট করে। ডকুমেন্টেশন Pathao মার্চেন্ট টিমের কাছে অনুরোধে পাওয়া যায়।

Steadfast Courier API REST, সবচেয়ে সহজ

হেডারে API key সহ ফ্ল্যাট REST API। অর্ডার তৈরি করুন, ট্র্যাকিং নিন। বাংলাদেশের সবচেয়ে সহজ কুরিয়ার API — কাস্টম ডেলিভারি ক্যারিয়ার মডিউলের জন্য ভালো সূচনাবিন্দু।

বাংলাদেশ ব্যাংক ফিড শুধু CSV/MT940

BRAC, Dutch-Bangla, City, Eastern — বেশিরভাগই শুধু CSV বা MT940 ফাইল এক্সপোর্ট দেয়, লাইভ API নেই। IBBL এবং কিছু নতুন ব্যাংক সীমিত API দেয়। লাইভ সিঙ্কের বদলে Odoo-র ব্যাংক স্টেটমেন্ট ইমপোর্ট ব্যবহার করুন।

NBR iBAS++ পাবলিক API নেই

NBR-এর ট্যাক্স রিটার্ন সিস্টেমে কোনো পাবলিক API নেই। ডেটা ওয়েব ইন্টারফেসের মাধ্যমে জমা দিতে হয়। Odoo প্রয়োজনীয় ফরম্যাট (Mushak 6.3 রিপোর্ট) এক্সপোর্ট করতে পারে, কিন্তু সরাসরি জমা দিতে পারে না।

ShurjoPay REST, বাংলাদেশি কার্ড

বাংলাদেশি কার্ড ও মোবাইল ব্যাংকিং কভার করা নতুন গেটওয়ে। JWT অথেন্টিকেশনসহ REST API। মিড-মার্কেটে গ্রহণযোগ্যতা বাড়ছে। ইন-হাউস ডেভেলপমেন্ট সক্ষমতা থাকা কোম্পানির জন্য উপযুক্ত।

বাংলাদেশের ফিনটেক ইকোসিস্টেম দ্রুত বাড়ছে, কিন্তু API-র মান এখনো উচ্চাকাঙ্ক্ষার পেছনে পড়ে আছে। বাজেট করার আগে জেনে নিন আপনি ঠিক কোন স্তরের ইন্টিগ্রেশন তৈরি করছেন।

Odoo API-র মূল বিষয়: XML-RPC, JSON-RPC এবং REST

Odoo তিনটি API ইন্টারফেস দেয়। কোনটি কোন কাজে ব্যবহার করবেন, সেটা বুঝে নেওয়াই আপনার ইন্টিগ্রেশন টিমের প্রথম সিদ্ধান্ত হওয়া উচিত।

/web/dataset/call_kw-এ Odoo-র JSON-RPC ইন্টারফেস সব Odoo ভার্সনে পাওয়া যায় এবং এটাই সবচেয়ে বেশি ব্যবহৃত ইন্টিগ্রেশন পদ্ধতি। প্রতিটি Odoo মডেল আর তার মেথড এখান থেকে অ্যাক্সেসযোগ্য — read, write, create, unlink, এবং আপনার নিজের সংজ্ঞায়িত যেকোনো কাস্টম মেথড। বাংলাদেশের বেশিরভাগ ইন্টিগ্রেশন ডেভেলপার এটাই ব্যবহার করেন, কারণ এতে বাড়তি সেটআপ লাগে না আর যেকোনো HTTP ক্লায়েন্টের সাথে কাজ করে।

উদাহরণ: অথেন্টিকেট করে সেল অর্ডার পড়া (Python)
import requests, json

url = "https://your-odoo.com"

# Step 1: Authenticate
auth = requests.post(f"{url}/web/dataset/call_kw", json={
    "jsonrpc": "2.0", "method": "call", "id": 1,
    "params": {
        "model": "res.users",
        "method": "authenticate",
        "args": ["your-db", "user@company.com", "password", {}],
        "kwargs": {}
    }
}).json()

uid = auth["result"]

# Step 2: Read confirmed sale orders
orders = requests.post(f"{url}/web/dataset/call_kw", json={
    "jsonrpc": "2.0", "method": "call", "id": 2,
    "params": {
        "model": "sale.order",
        "method": "search_read",
        "args": [[["state", "=", "sale"]]],
        "kwargs": {"fields": ["name", "partner_id", "amount_total"], "limit": 50}
    }
}).json()

print(orders["result"])

XML-RPC — পুরনো কিন্তু স্থিতিশীল, সব ভার্সনে পাওয়া যায়

XML-RPC হলো Odoo-র পুরনো ইন্টারফেস, Odoo 8 থেকে পাওয়া যাচ্ছে। এটি দুটি এন্ডপয়েন্টের মাধ্যমে কাজ করে: /xmlrpc/2/common (অথেন্টিকেশনের জন্য) এবং /xmlrpc/2/object (সব মডেল অপারেশনের জন্য)। এটি JSON-RPC-এর চেয়ে একটু বেশি ভার্বোস, তবে সম্পূর্ণ স্থিতিশীল এবং বাংলাদেশের অনেক দীর্ঘমেয়াদি ইন্টিগ্রেশনে ব্যবহৃত হয়।

XML-RPC ব্যবহার করুন যখন: পুরনো Odoo ভার্সন (12, 13, 14) নিয়ে কাজ করছেন, অথবা Odoo-র অফিসিয়াল odoorpc Python লাইব্রেরি ব্যবহার করছেন যা XML-RPC-কে পরিষ্কারভাবে র‍্যাপ করে।

REST API — Odoo 16-এ নতুন, আধুনিক ইন্টিগ্রেশনের জন্য পরিষ্কার

Odoo 16-এ নির্দিষ্ট মডেলের জন্য /api/ এন্ডপয়েন্টে একটি প্রকৃত REST API যোগ হয়েছে। এটি API key অথেন্টিকেশন ব্যবহার করে (সেশন ম্যানেজমেন্টের দরকার নেই) এবং পরিষ্কার JSON রিটার্ন করে। Odoo 18 পর্যন্ত, REST API সবচেয়ে কমন অবজেক্টগুলো কভার করে: /api/sale.order, /api/res.partner, /api/stock.picking ইত্যাদি।

Odoo 16+-এ নতুন ইন্টিগ্রেশনের জন্য REST API-ই সঠিক পছন্দ, কারণ এতে সেশন কুকি ম্যানেজমেন্টের দরকার নেই এবং সুরক্ষিত করা সহজ। Settings → Users → Your User → API Keys ট্যাব থেকে একটি API key তৈরি করুন।

অথেন্টিকেশন ও API নিরাপত্তা

বাংলাদেশের ইন্টিগ্রেশনগুলো সবচেয়ে বেশি ব্যর্থ হয় ঠিক এই জায়গাতেই — কোড ভুল হওয়ার কারণে নয়, বরং সিকিউরিটি কনফিগারেশন ভালোভাবে চিন্তা না করার কারণে। বেছে নেওয়ার জন্য তিনটি প্যাটার্ন আছে:

  1. API Key অথেন্টিকেশন (Odoo 16+-এর জন্য প্রস্তাবিত) প্রতিটি বাহ্যিক সিস্টেমের জন্য আলাদা API key তৈরি করুন। Settings → Technical → API Keys (অথবা প্রতি-ইউজার API Keys ট্যাব)। কী-টিকে ইন্টিগ্রেশন সার্ভারে এনভায়রনমেন্ট ভ্যারিয়েবল হিসেবে রাখুন — কখনো সোর্স কোডে নয়। প্রতি ৯০ দিনে কী রোটেট করুন। প্রতিটি ইন্টিগ্রেশনের জন্য আলাদা কী ব্যবহার করুন, যাতে বাকিদের প্রভাবিত না করে একটি রিভোক করা যায়।
  2. নিবেদিত ইন্টিগ্রেশন ইউজার (সব ভার্সনে) ইন্টিগ্রেশনের কাজের জন্য প্রয়োজনীয় ন্যূনতম পারমিশনসহ একটি আলাদা Odoo ইউজার তৈরি করুন (যেমন, api-integration@company.com)। অ্যাডমিন অ্যাকাউন্ট ব্যবহার করবেন না। কী ফাঁস হয়ে গেলেও, ন্যূনতম-পারমিশনযুক্ত ইউজার ক্ষতির পরিধি সীমিত রাখে। রেস্ট্রিক্টেড ইউজার রোল কনফিগার করার জন্য দেখুন Odoo ইউজার অ্যাক্সেস রাইটস গাইড।
  3. Nginx/সার্ভার কনফিগের মাধ্যমে IP হোয়াইটলিস্টিং আপনার ইন্টিগ্রেশন সার্ভারে যদি স্ট্যাটিক IP থাকে (বাংলাদেশের অফিস সার্ভার ও ক্লাউড VM-এর জন্য প্রস্তাবিত), ওয়েব সার্ভার লেভেলে API অ্যাক্সেস সীমিত করুন। Nginx-এর allow/deny নিয়ম নিশ্চিত করে যে ক্রেডেনশিয়াল ফাঁস হলেও, যেকোনো IP থেকে API অ্যাক্সেস করা যাবে না।
  4. System Parameters-এ কী সংরক্ষণ করুন Odoo নিজেই যেসব থার্ড-পার্টি API key কল করে (যেমন bKash API key, কুরিয়ার API key), সেগুলো সংরক্ষণের জন্য Settings → Technical → System Parameters ব্যবহার করুন। স্পষ্টভাবে নাম দিন: bkash.app_key, steadfast.api_key। System Parameters-এর অ্যাক্সেস শুধু অ্যাডমিনের মধ্যে সীমাবদ্ধ রাখুন।
সিকিউরিটি সতর্কতা

Git রিপোজিটরিতে কখনো API key বা Odoo ক্রেডেনশিয়াল কমিট করবেন না। বাংলাদেশের ডেভেলপমেন্ট টিমগুলো প্রায়ই কনফিগ ফাইলে API key GitHub-এ পুশ করে দেয় — এটি একটি গুরুতর সিকিউরিটি ঝুঁকি। এনভায়রনমেন্ট ভ্যারিয়েবল বা এনক্রিপ্টেড সিক্রেট স্টোর ব্যবহার করুন (AWS Secrets Manager, HashiCorp Vault, অথবা এমনকি একটি git-ignored .env ফাইল)।

bKash Merchant API ইন্টিগ্রেশন

ইন্টিগ্রেশনের ধরন: payment.provider এবং payment.transaction মডেল এক্সটেন্ড করা একটি কাস্টম Odoo পেমেন্ট প্রোভাইডার মডিউল। bKash OAuth 2.0 ব্যবহার করে — প্রথমে একটি টোকেন নিতে হয় (/tokenized/checkout/token/grant-এ POST), তারপর সেই টোকেন দিয়ে পেমেন্ট তৈরি করতে হয় (/tokenized/checkout/create-এ POST), এরপর ইউজারকে bKash-এর পেমেন্ট পেজে রিডাইরেক্ট করতে হয়, আর শেষে আপনার ওয়েবহুক URL-এ কলব্যাক ক্যাপচার করতে হয়।

বাংলাদেশ-নির্দিষ্ট রিকোয়ারমেন্ট:

  • রেজিস্টার্ড ব্যবসাসহ (ট্রেড লাইসেন্স + TIN) একটি সক্রিয় bKash মার্চেন্ট অ্যাকাউন্ট থাকতে হবে।
  • প্রোডাকশন ক্রেডেনশিয়ালের জন্য IP হোয়াইটলিস্টিং লাগে — আপনার Odoo সার্ভারের পাবলিক IP bKash-এর কাছে রেজিস্টার্ড থাকতে হবে।
  • bKash-এর একটি কলব্যাক URL লাগে যা HTTPS-এ অ্যাক্সেসযোগ্য। প্রোডাকশনে সেলফ-সাইনড সার্টিফিকেট গ্রহণযোগ্য নয়।
  • প্রোডাকশন ক্রেডেনশিয়াল চাওয়ার আগে tokenized.sandbox.bka.sh-এর স্যান্ডবক্সে টেস্ট করুন।

Odoo মডিউলটি যা করে: কোনো বাংলাদেশি গ্রাহক যখন bKash-এর মাধ্যমে একটি Odoo ইনভয়েস পরিশোধ করেন, পেমেন্ট ফর্মটি bKash-এ রিডাইরেক্ট হয়, পেমেন্ট সম্পন্ন হয়, Odoo-র কলব্যাক URL-এ ফিরে আসে, আর মডিউলটি স্বয়ংক্রিয়ভাবে ইনভয়েসকে পরিশোধিত হিসেবে চিহ্নিত করে এবং bKash ব্যাংক জার্নালে জার্নাল এন্ট্রি তৈরি করে।

B2C-র জন্য সবচেয়ে সহজ

SSLCommerz ইন্টিগ্রেশন

একাধিক পেমেন্ট পদ্ধতি (bKash, Nagad, Rocket, কার্ড, ইন্টারনেট ব্যাংকিং) একটি মাত্র গেটওয়ের মাধ্যমে গ্রহণ করতে চাইলে, প্রতিটির জন্য আলাদা ইন্টিগ্রেশন তৈরি না করে SSLCommerz-ই সঠিক পছন্দ। জটিলতা SSLCommerz নিজেই সামলায় এবং আপনার সেটলমেন্ট অ্যাকাউন্টে ফান্ড ভাগ করে দেয়।

SSLCommerz GitHub-এ একটি Python SDK দেয়। Odoo ইন্টিগ্রেশনের প্যাটার্ন এরকম: ইনভয়েস পেমেন্টে ক্লিক করলে একটি SSLCommerz সেশন তৈরি হয় (/gwprocess/v4/api.php-এ POST), SSLCommerz-এর হোস্টেড চেকআউটে রিডাইরেক্ট হয়, আপনার Odoo ওয়েবহুকে IPN (Instant Payment Notification) আসে, হ্যাশ সিগনেচার ভ্যালিডেট করা হয়, আর পেমেন্ট স্বয়ংক্রিয়ভাবে রিকনসাইল হয়ে যায়।

SSLCommerz IPN ভ্যালিডেশন (Python)
import hashlib

def validate_sslcommerz_ipn(data, store_passwd):
    """Verify SSLCommerz IPN hash before marking payment as received."""
    received_hash = data.get("verify_sign")
    data_without_sign = {k: v for k, v in data.items()
                         if k not in ("verify_sign", "verify_key")}
    # Sort keys and concat with store password
    sorted_data = dict(sorted(data_without_sign.items()))
    sorted_data["store_passwd"] = hashlib.md5(
        store_passwd.encode()).hexdigest()
    hash_str = "&".join(f"{k}={v}" for k, v in sorted_data.items())
    expected = hashlib.md5(hash_str.encode()).hexdigest()
    return received_hash == expected

এই হ্যাশ ভ্যালিডেট না করে কখনো পেমেন্টকে গৃহীত হিসেবে চিহ্নিত করবেন না। ভ্যালিডেশন বাদ দেওয়াই বাংলাদেশি ডেভেলপারদের করা #1 SSLCommerz সিকিউরিটি ভুল।

BRAC Bank, Dutch-Bangla, City Bank, Eastern Bank: CSV/MT940 ইমপোর্ট

2026 সাল পর্যন্ত, বাংলাদেশের প্রধান কমার্শিয়াল ব্যাংকগুলো — BRAC, Dutch-Bangla, City Bank, Eastern Bank, Mutual Trust Bank — ব্যবসায়িক গ্রাহকদের জন্য কোনো লাইভ কর্পোরেট ব্যাংকিং API দেয় না। তারা যা দেয়:

  • CSV স্টেটমেন্ট এক্সপোর্ট: ইন্টারনেট ব্যাংকিং পোর্টাল থেকে পাওয়া যায়। প্রতিদিন বা সাপ্তাহিক ডাউনলোড করে Accounting → Bank Statements → Import-এর মাধ্যমে Odoo-তে ইমপোর্ট করুন।
  • MT940 ফরম্যাট: কিছু ব্যাংক (বিশেষত যাদের SWIFT কানেক্টিভিটি আছে) MT940 ফরম্যাট এক্সপোর্ট দেয়। Odoo নেটিভভাবে MT940 ইমপোর্ট সাপোর্ট করে।
  • OFX ফরম্যাট: বিরল, তবে কিছু পোর্টালে পাওয়া যায়। এটিও Odoo নেটিভভাবে সাপোর্ট করে।

ব্যবহারিক পরামর্শ: একটি শিডিউলড স্ক্রিপ্টের মাধ্যমে CSV ডাউনলোড অটোমেট করুন (ব্যাংক পোর্টালে লগইন করে স্টেটমেন্ট ডাউনলোড করতে Selenium বা Playwright ব্যবহার করে) এবং তারপর ফাইলটি Odoo-র ব্যাংক স্টেটমেন্ট ইমপোর্ট API-তে পুশ করুন। এতে লাইভ API ছাড়াই প্রায়-স্বয়ংক্রিয় ব্যাংক রিকনসিলিয়েশন পাবেন।

গুরুত্বপূর্ণ

ব্যাংক পোর্টালে স্বয়ংক্রিয় ব্রাউজার লগইন আপনার ব্যাংকের শর্তাবলী লঙ্ঘন করতে পারে। আপনার কর্পোরেট ইন্টারনেট ব্যাংকিং পোর্টালে ব্রাউজার অটোমেশন বাস্তবায়নের আগে আপনার রিলেশনশিপ ম্যানেজারের সাথে যাচাই করে নিন। কিছু ব্যাংক OTP-ভিত্তিক অ্যাক্সেস দেয় যা এমনিতেই অটোমেশনকে অব্যবহারযোগ্য করে তোলে — এক্ষেত্রে মানুষের সহায়তায় দৈনিক ইমপোর্টই একমাত্র উপায় হতে পারে।

API পাওয়া যায়

IDLC Finance, IPDC: কর্পোরেট ফাইন্যান্স API (সীমিত)

বাংলাদেশের অল্প কিছু NBFI এবং নতুন ডিজিটাল ব্যাংক কর্পোরেট API অ্যাক্সেস দেওয়া শুরু করেছে। আপনার কোম্পানির ব্যাংক যদি কর্পোরেট API অ্যাক্সেস দেয়, তাহলে ফাইল আপলোডের বদলে Odoo-র account.bank.statement.line মডেল ব্যবহার করে প্রোগ্রামেটিকভাবে লেনদেন ইমপোর্ট করুন। আপনার ব্যাংক যদি এই সুবিধা দেয়, তাহলে এটাই নেওয়ার মতো পদ্ধতি।

শিপিং ও ডেলিভারি API ইন্টিগ্রেশন

বাংলাদেশের ই-কমার্স আর B2B ফুলফিলমেন্ট কোম্পানির জন্য, কুরিয়ার API ইন্টিগ্রেশন প্রায়ই তৈরি করার মতো সবচেয়ে বেশি ROI-যুক্ত ইন্টিগ্রেশন। শিপমেন্ট তৈরি, লেবেল প্রিন্টিং আর ট্র্যাকিং স্ট্যাটাস সিঙ্ক অটোমেট করলে, কোনো অর্থবহ অর্ডার ভলিউমে প্রতিদিন ম্যানুয়াল ডেটা এন্ট্রির অনেক ঘণ্টা বেঁচে যায়।

প্রথমে তৈরি করার প্রস্তাবিত

Steadfast Courier API — সবচেয়ে সহজ বাংলাদেশ কুরিয়ার ইন্টিগ্রেশন

বাংলাদেশের কুরিয়ার মার্কেটে Steadfast-এর API সবচেয়ে সহজ। API key অথেন্টিকেশন (হেডারে Api-Key ও Secret-Key পাস করে), ফ্ল্যাট REST এন্ডপয়েন্ট, সরল রেসপন্স স্ট্রাকচার। ইন্টিগ্রেশনটি Odoo-র stock.delivery.carrier মডেল এক্সটেন্ড করে।

Steadfast: একটি শিপমেন্ট তৈরি করা (Python)
import requests

STEADFAST_BASE = "https://portal.packzy.com/api/v1"
headers = {
    "Api-Key": "YOUR_API_KEY",
    "Secret-Key": "YOUR_SECRET_KEY",
    "Content-Type": "application/json"
}

def create_steadfast_order(invoice, customer, address, cod_amount):
    payload = {
        "invoice": invoice,         # Your order reference
        "recipient_name": customer,
        "recipient_phone": address["phone"],
        "recipient_address": address["street"],
        "cod_amount": cod_amount    # 0 for prepaid
    }
    resp = requests.post(
        f"{STEADFAST_BASE}/create_order",
        json=payload, headers=headers
    )
    data = resp.json()
    return data.get("consignment", {}).get("tracking_code")

রিটার্ন হওয়া tracking_code-টি Odoo-র stock.picking রেকর্ডে সংরক্ষণ করুন। Steadfast-এর স্ট্যাটাস এন্ডপয়েন্ট পোল করতে এবং Odoo-তে ডেলিভারি স্ট্যাটাস স্বয়ংক্রিয়ভাবে আপডেট করতে একটি শিডিউলড অ্যাকশন ব্যবহার করুন।

ওয়েবহুক সাপোর্ট

Pathao Courier API — ওয়েবহুক-ভিত্তিক স্ট্যাটাস আপডেট

Pathao-র কুরিয়ার API ওয়েবহুক কলব্যাক সাপোর্ট করে — শিপমেন্টের স্ট্যাটাস বদলালে (পিকড, ইন-ট্রানজিট, ডেলিভার্ড, রিটার্নড) Pathao নিজেই আপনার Odoo সার্ভারে স্ট্যাটাস আপডেট পাঠায়। এটি পোলিংয়ের চেয়ে বেশি কার্যকর। Pathao-র মার্চেন্ট পোর্টালে আপনার Odoo কন্ট্রোলার URL-কে ওয়েবহুক এন্ডপয়েন্ট হিসেবে রেজিস্টার করুন, তারপর একটি Odoo কন্ট্রোলার লিখুন যা POST রিকোয়েস্ট গ্রহণ করে সংশ্লিষ্ট stock.picking রেকর্ড আপডেট করে।

Pathao-র জন্যও মার্চেন্ট অনবোর্ডিং লাগে এবং ক্রেডেনশিয়াল তাদের লজিস্টিকস বিজনেস টিমের মাধ্যমে পাওয়া যায়। Pathao for Business পোর্টালের মাধ্যমে যোগাযোগ করুন।

এগুলোও পাওয়া যায়

Redx ও eCourier

Redx এবং eCourier দুটোই API key অথেন্টিকেশনসহ REST API দেয়। Redx-এর ডকুমেন্টেশন তাদের মার্চেন্ট পোর্টালের মাধ্যমে পাওয়া যায়। zone-ভিত্তিক প্রাইসিং ক্যালকুলেশনসহ eCourier API একটু বেশি জটিল। ইন্টিগ্রেশনের প্যাটার্ন Steadfast-এর মতোই — পিকিং ভ্যালিডেশনে অর্ডার তৈরি, ট্র্যাকিং কোড সংরক্ষণ, আর স্ট্যাটাস আপডেটের জন্য পোল করা বা ওয়েবহুক গ্রহণ করা।

NBR ও ট্যাক্স সিস্টেম: আসলে কী সম্ভব

বাংলাদেশের অনেক ব্যবসা জিজ্ঞেস করে Odoo সরাসরি NBR-এ Mushak রিপোর্ট বা VAT রিটার্ন জমা দিতে পারে কিনা। সত্যিকারের উত্তর: সরাসরি নয় — তবে Odoo ঠিক সেই ফরম্যাটে ডেটা তৈরি করতে পারে যা NBR-এর দরকার।

NBR-এর iBAS++ সিস্টেম (যেখানে সরকারি ট্যাক্স জমা হয়) এবং Mushak অনলাইন পোর্টাল (VAT রিটার্ন) — উভয়ের জন্যই 2026 সাল পর্যন্ত ব্রাউজার ইন্টারফেসের মাধ্যমে ম্যানুয়াল সাবমিশন লাগে। স্বয়ংক্রিয় সাবমিশনের জন্য কোনো পাবলিক REST API নেই।

Odoo যা করতে পারে:

  • Mushak 6.3 (সেলস VAT রেজিস্টার), 6.4 (পারচেজ VAT রেজিস্টার), এবং 6.5 (ক্রেডিট নোট রেজিস্টার) PDF বা CSV এক্সপোর্ট হিসেবে তৈরি করা — ঠিক NBR ফাইলিংয়ের জন্য প্রয়োজনীয় ফরম্যাটে।
  • ভেন্ডর পেমেন্টে TDS (Tax Deducted at Source) হিসাব করা এবং 108 ও 108A সার্টিফিকেট তৈরি করা।
  • ফাইলিংয়ের আগে মাসিক রিকনসিলিয়েশনের জন্য VAT পেয়েবল/রিসিভেবল ট্র্যাক করা।
  • VAT Online পোর্টালে আপলোডের জন্য প্রয়োজনীয় Excel ফরম্যাটে VAT রিটার্ন ডেটা এক্সপোর্ট করা।

ইন্টিগ্রেশনের ফাঁকটি রয়ে যায় চূড়ান্ত সাবমিশন ধাপে — যার জন্য এখনো একজন মানুষকে NBR পোর্টালে লগইন করে ডেটা আপলোড বা এন্টার করতে হয়। সেই ধাপ পর্যন্ত সবকিছুই Odoo সেতুবন্ধন করে দেয়।

বাংলাদেশের ব্যবসার জন্য সাধারণ ইন্টিগ্রেশন প্যাটার্ন

প্যাটার্ন ১

ই-কমার্স সিঙ্ক: WooCommerce / কাস্টম ওয়েবসাইট → Odoo

আলাদা WooCommerce স্টোরসহ বাংলাদেশের অনলাইন রিটেইলারদের অর্ডার, কাস্টমার আর ইনভেন্টরি Odoo-র সাথে সিঙ্ক করা দরকার। স্ট্যান্ডার্ড প্যাটার্ন: WooCommerce ওয়েবহুক (order.created-এ) একটি Odoo JSON-RPC এন্ডপয়েন্ট কল করে sale.order তৈরি করে, কনফার্ম করে, আর স্টক রিজার্ভেশন ট্রিগার করে। ইনভেন্টরি লেভেল প্রতি ১৫ মিনিটে একটি ক্রন জবের মাধ্যমে — যা Odoo-র product.product মডেল কোয়েরি করে — শিডিউল অনুযায়ী WooCommerce-এ ফিরে সিঙ্ক হয়।

পাওয়া যায় এমন টুল: Odoo Connector for WooCommerce (GitHub-এ OCA প্রজেক্ট), অথবা WooCommerce ও Odoo-র API-র মধ্যে মিডলওয়্যার হিসেবে Python FastAPI/Flask দিয়ে একটি হালকা ওয়েবহুক হ্যান্ডলার তৈরি করুন।

প্যাটার্ন ২

নো-কোড মিডলওয়্যার: সাধারণ বাংলাদেশ ইন্টিগ্রেশনের জন্য n8n

কাস্টম ডেভেলপমেন্ট ছাড়া ইন্টিগ্রেশন চাওয়া বাংলাদেশি ব্যবসার জন্য n8n (ওপেন-সোর্স ওয়ার্কফ্লো অটোমেশন) একটি চমৎকার মিডল লেয়ার। n8n-এ নেটিভ Odoo নোড আছে এবং মাসে ৳1,500-এর ক্লাউড VM-এ সেলফ-হোস্ট করা যায়। সাধারণ ব্যবহার: Google Forms → Odoo লিড, ইমেইল → Odoo সাপোর্ট টিকেট, Excel/Google Sheets ইমপোর্ট → Odoo প্রোডাক্ট/কাস্টমার রেকর্ড।

হাই-ভলিউম, রিয়েল-টাইম ইন্টিগ্রেশনের জন্য (যেমন মিনিটে ১০০+ ট্রানজেকশনের SSLCommerz IPN কলব্যাক) n8n উপযুক্ত নয়। এসব ক্ষেত্রে একটি যথাযথ Odoo কাস্টম মডিউলই সঠিক উত্তর।

প্যাটার্ন ৩

ডেটা বের করে পাঠানো: Odoo → বাহ্যিক BI / রিপোর্টিং টুল

কিছু বাংলাদেশি কোম্পানি CEO-র জন্য Power BI, Google Looker Studio বা একটি কাস্টম ড্যাশবোর্ডে Odoo-র ডেটা পাঠাতে চায়। প্যাটার্নটি এরকম: একটি শিডিউলড Python স্ক্রিপ্ট Odoo-র API কোয়েরি করে (সংশ্লিষ্ট মডেলে search_read), ডেটা রূপান্তর করে, আর একটি PostgreSQL ডেটাবেস বা Google Sheets-এ লেখে, যার সাথে Power BI বা Looker Studio সংযুক্ত থাকে।

বিকল্পভাবে, রিড-অনলি রিপোর্টিং ইউজার ব্যবহার করে Power BI-কে সরাসরি Odoo-র PostgreSQL ডেটাবেসের সাথে (সেলফ-হোস্টেড হলে) সংযুক্ত করুন। বাংলাদেশে Odoo-র অন-প্রিমাইজ ডেপ্লয়মেন্টের জন্য এটাই সবচেয়ে সহজ পদ্ধতি।

API কানেক্টিভিটি সমস্যা সমাধান

সমস্যা: প্রতিটি API কলে "odoo.exceptions.AccessDenied"
ইন্টিগ্রেশন ইউজারের পাসওয়ার্ড ভুল, অথবা ইউজারটি সঠিক ডেটাবেসে নেই। যাচাই করুন: ডেটাবেসের নাম হুবহু মিলছে কিনা (কেস-সেনসিটিভ), ইউজার সক্রিয় আছে কিনা (আর্কাইভড নয়), আর পাসওয়ার্ডের মেয়াদ শেষ হয়নি। Odoo 17+ ব্যবহার করলে, ইউজারে 2FA চালু আছে কিনা দেখুন — API key অথ 2FA বাইপাস করে; সেশন-ভিত্তিক অথ করে না।

সমস্যা: টেস্টিংয়ে API কাজ করে কিন্তু বাংলাদেশ প্রোডাকশন সার্ভার থেকে ব্যর্থ হয়
সবচেয়ে সম্ভাব্য কারণ: বাংলাদেশ সার্ভারের IP বাহ্যিক API প্রোভাইডার (bKash, SSLCommerz ইত্যাদি) ব্লক করে দিয়েছে। IP হোয়াইটলিস্টিং চেক করুন। আপনার বাংলাদেশ সার্ভার যদি শেয়ার্ড/ডাইনামিক IP ব্যবহার করে (BTCL, Grameenphone হোম প্ল্যানের মতো ISP-তে সাধারণ), তাহলে একটি স্ট্যাটিক IP লাগবে — আপনার ISP-র কাছে অনুরোধ করে পাওয়া যায়, অথবা ফিক্সড পাবলিক IP-সহ একটি ক্লাউড VM ব্যবহার করুন।

সমস্যা: বাংলাদেশ সার্ভার থেকে SSL সার্টিফিকেট এরর
বাংলাদেশ সার্ভারে প্রায়ই পুরনো CA সার্টিফিকেট বান্ডেল থাকে। Ubuntu/Debian-এ sudo update-ca-certificates চালান অথবা ca-certificates প্যাকেজ ইনস্টল করুন। আপনার সার্ভারের ঘড়ি সঠিক (NTP-সিঙ্কড) কিনা যাচাই করুন — সার্ভারের ঘড়ি ৫ মিনিটের বেশি ভুল থাকলে সার্টিফিকেট ভ্যালিডেশন ব্যর্থ হয়, যা ভুলভাবে কনফিগার করা বাংলাদেশি VM-এ অবাক করার মতো সাধারণ।

সমস্যা: bKash/SSLCommerz থেকে ওয়েবহুক কলব্যাক Odoo-তে পৌঁছাচ্ছে না
চেক করুন আপনার Odoo সার্ভার ইন্টারনেট থেকে পোর্ট 443 (HTTPS)-এ অ্যাক্সেসযোগ্য কিনা। বাংলাদেশের অনেক অন-প্রিমাইজ সার্ভার পোর্ট ফরওয়ার্ডিং কনফিগার না করা NAT রাউটারের পেছনে থাকে। ডেভেলপমেন্ট/টেস্টিংয়ের জন্য ngrok-এর মতো একটি সার্ভিস ব্যবহার করুন। প্রোডাকশনের জন্য, নিশ্চিত করুন আপনার ফায়ারওয়াল ও রাউটার পোর্ট 443 আপনার Odoo সার্ভারে ফরওয়ার্ড করছে এবং আপনার একটি বৈধ SSL সার্টিফিকেট আছে (Let's Encrypt পুরোপুরি কাজ করে)।

সব ইন্টিগ্রেশন সিকিউরিটির ভিত্তি যে অ্যাক্সেস রাইটস কনফিগারেশন, তা নিয়ে বিস্তারিত আছে Odoo ইউজার রোল ও অ্যাক্সেস রাইটস গাইড-এ — কীভাবে সঠিকভাবে ন্যূনতম-পারমিশনযুক্ত ইন্টিগ্রেশন ইউজার তৈরি করবেন তা জানতে। আর যেসব মাল্টি-কোম্পানি সেটআপে API ইন্টিগ্রেশন আরও জটিল হয়ে ওঠে, সেজন্য Odoo মাল্টি-কোম্পানি সেটআপ গাইড-এ ব্যাখ্যা করা হয়েছে ডেটাবেস আর্কিটেকচার — যা ঠিক করে দেয় আপনার API কল কোন কোম্পানির ডেটা দেখতে পাবে।

ইন্টিগ্রেশন অ্যাসেসমেন্ট

আপনার বাংলাদেশি ব্যবসার যদি Odoo-কে bKash, কোনো কুরিয়ার API, ব্যাংকিং সিস্টেম বা কাস্টম থার্ড-পার্টি টুলের সাথে সংযুক্ত করা দরকার হয়, আমি স্কোপ মূল্যায়ন করে বিল্ড বনাম বাই বনাম মিডলওয়্যার নিয়ে পরামর্শ দিতে পারি। ইন্টিগ্রেশন স্কোপিং কলের জন্য যোগাযোগ করুন →

সচরাচর জিজ্ঞাসা

Odoo-র কি REST API আছে?

হ্যাঁ। Odoo 16 এবং পরবর্তী ভার্সনগুলো নির্দিষ্ট অবজেক্টের জন্য /api/ এন্ডপয়েন্টে একটি নেটিভ REST API দেয়। আগের ভার্সনগুলো /web/dataset/call_kw-এ XML-RPC বা JSON-RPC ব্যবহার করে। বাংলাদেশের ইন্টিগ্রেশনে JSON-RPC ইন্টারফেসই সবচেয়ে বেশি ব্যবহৃত হয়, কারণ এটি যেকোনো HTTP ক্লায়েন্টের সাথে কাজ করে আর বিশেষ কোনো SDK-র দরকার হয় না।

bKash কি সরাসরি Odoo-র সাথে ইন্টিগ্রেট করা যায়?

হ্যাঁ, তবে নেটিভ Odoo মডিউল দিয়ে নয়। bKash মার্চেন্ট API (REST, OAuth 2.0) একটি কাস্টম পেমেন্ট প্রোভাইডার মডিউলের মাধ্যমে সংযুক্ত করতে হবে। প্রোডাকশন ইন্টিগ্রেশনের আগে bKash মার্চেন্ট API-র জন্য একটি রেজিস্টার্ড ব্যবসায়িক অ্যাকাউন্ট, IP হোয়াইটলিস্টিং এবং bKash-এর স্যান্ডবক্স ক্রেডেনশিয়াল লাগে। বাংলাদেশের বেশিরভাগ Odoo পার্টনার এটিকে একটি কাস্টম মডিউল হিসেবে তৈরি করে যা Odoo-র payment.provider মডেল এক্সটেন্ড করে।

বাংলাদেশে Odoo-র সাথে কোন শিপিং API কাজ করে?

Pathao Courier, Steadfast Courier, Redx, এবং eCourier হলো বাংলাদেশের প্রধান ডেলিভারি API। 2026 সাল পর্যন্ত App Store-এ এদের কোনোটিরই অফিসিয়াল Odoo মডিউল নেই। ইন্টিগ্রেশনের জন্য একটি কাস্টম ডেলিভারি ক্যারিয়ার মডিউল লাগে। Steadfast-এর API সবচেয়ে সহজ (API key অথসহ ফ্ল্যাট REST) এবং কাস্টম ডেভেলপমেন্টের জন্য সবচেয়ে সহজ সূচনাবিন্দু।

Odoo-তে API key সংরক্ষণের সবচেয়ে নিরাপদ উপায় কী?

থার্ড-পার্টি API key ডেটাবেসে সংরক্ষণের জন্য Settings → Technical → System Parameters ব্যবহার করুন। বাহ্যিক সিস্টেমকে দেওয়া Odoo-র নিজস্ব API key-র জন্য, ইউজারের API Keys ট্যাব থেকে প্রতিটি ইন্টিগ্রেশনের জন্য আলাদা API key তৈরি করুন। কখনো Git-এ API key কমিট করবেন না। অ্যাক্সেস রাইটস কনফিগারেশনের মাধ্যমে System Parameters-এর অ্যাক্সেস শুধু অ্যাডমিনিস্ট্রেটর রোলের মধ্যে সীমাবদ্ধ রাখুন।
